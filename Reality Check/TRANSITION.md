## Если прошлая сессия оборвалась

Агенты пишут прямо в рабочее дерево на сервере, поэтому после обрыва там могут лежать незакоммиченные экзамены (`git status`). Для каждого такого файла: `python3 -I "Reality Check/tools/verify_exam.py" <файл>` — если OK, это готовый перевод без рецензии: отрецензировать по процедуре и закоммитить (оглавление — `toc.py --index`, см. ниже); если FAIL — агент не успел, вернуть файл командой `git checkout -- <файл>` и перевести заново. Сверяться со списком «Что сделано» выше и со столбцом «Формат» оглавления.

## Процедура для одного пакета

1. `git pull`. Убедиться, что рабочее дерево чистое (`git status`).
2. Запустить агентов-составителей (по одному на экзамен, все экзамены этапа параллельно) с заданием «Составитель» ниже. **Модель всех агентов, включая рецензентов, — Opus 5.5** (в Claude Code: параметр `model: "opus"`; решение владельца 2026-10-30, до этого — Fable 5.1). Этапы выполнять по одному: перед каждым следующим этапом сообщить владельцу оценку времени и доли недельной квоты и дождаться разрешения.
3. Как только составитель отчитался, сразу запустить на этот экзамен рецензента с заданием «Рецензент» ниже (тоже Opus 5.5). В задание рецензента полезно добавить сомнения составителя (что проверить особо), но не его решения. Рецензент сам дописывает пометку «Независимая рецензия: <дата>.» в строку «Изменения».
4. Каждый экзамен коммитить и пушить сразу после рецензии, не дожидаясь всего этапа:

   ```
   python3 -I "Reality Check/tools/verify_exam.py" "<файл>"        # должно быть OK
   git add -- "<файл>"
   python3 -I "Reality Check/tools/toc.py" --index                # оглавление только по тому, что в индексе
   git add "Reality Check/README.md"
   git commit -m "Reality Check: <Код> переведён в новый формат, независимая рецензия"
   git push
   ```

   Режим `--index` важен: соседние агенты в это время пишут в рабочее дерево, и обычный `toc.py` занёс бы их недописанные файлы в оглавление.
5. Не делать `git add -A`, `git stash`, `git checkout -- .` пока работают агенты: они пишут в рабочее дерево. Файлы, которые координатор правил сам (CLAUDE.md, PLAN.md, TRANSITION.md), добавлять в коммит осознанно.
6. **Отчёты агентов владельцу пересказывать без спойлеров.** Владелец (Leo) сам сдаёт эти экзамены: не называть ответы, истинность утверждений B, контрпримеры и ходы решений — только что исправлено и почему, на уровне «ответ на A2 был напечатан в условии D1», «в ключе C3 была ошибка в критериях».
7. После этапа: обновить «Что сделано» и «Ориентир по ресурсам» выше (фактический расход — сумма `subagent_tokens` из уведомлений об окончании агентов).
