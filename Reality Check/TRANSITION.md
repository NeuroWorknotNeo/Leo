## Процедура для одного пакета

1. `git pull`. Убедиться, что рабочее дерево чистое (`git status`).
2. Запустить агентов-составителей (по одному на экзамен, параллельно 7–9 штук) с заданием «Составитель» ниже. **Модель агентов — самая сильная доступная** (в Claude Code: параметр `model: "fable"`), даже если диалог ведёт Opus; это просьба владельца.
3. По отчёту составителя запустить рецензента с заданием «Рецензент» ниже (тоже сильная модель). Рецензент сам дописывает пометку «Независимая рецензия: <дата>.» в строку «Изменения».
4. Когда пакет готов: `python3 -I "Reality Check/tools/verify_exam.py" <файлы пакета>` — все OK; `python3 -I "Reality Check/tools/toc.py"`; `git add` **только** файлов пакета, README.md и того, что менялось осознанно; коммит вида «Reality Check: экзамены этапа N переведены в новый формат (коды)»; `git push`.
5. Не делать `git add -A`, `git stash`, `git checkout -- .` пока работают агенты: они пишут в рабочее дерево.

Выдавать экзамен в состоянии «ждёт рецензии» можно; при проверке попытки по нему сверять ключ особенно внимательно.
