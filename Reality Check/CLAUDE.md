# Reality Check — инструкции для Claude и других ИИ

Папка `Reality Check/` хранит программу изучения математики (`PLAN.md`) и экзамены ко всем её дисциплинам. Владелец программы и репозитория — студент **Leo**. Все файлы и общение — на русском языке. Этот файл фиксирует, как устроена совместная работа: что делать по каким просьбам и какого качества должны быть результаты. Правила для студента изложены в `README.md`, протокол проверки — в `GRADING.md`, правила вариантов — в `Variants/README.md`, правила для попыток — в `Students/README.md`; при расхождении этот файл и `GRADING.md` главнее.

## Структура

```
Reality Check/
  PLAN.md                               — программа: Часть I — этапы с галочками, Часть II — карта связей,
                                           Часть III — атлас (карточки дисциплин с якорями #a1, #g9 …, банк КТ)
  README.md                             — формат экзамена, уровни, как сдавать, журнал попыток, оглавление
  GRADING.md                            — протокол проверки
  CLAUDE.md                             — этот файл
  Exams/<Область>/<Код>_<Название>.md   — основной экзамен (v1) с ключом; 78 экзаменов
  Variants/<Код>/vN.md                  — варианты для пересдач и для других студентов
  Students/<Имя>/<Код>/<дата выдачи>/   — попытки: exam.pdf, notes.md, решения, REPORT.md
  tools/exam_pdf.py                     — сборка PDF с условиями; --zip собирает архив
  tools/verify_exam.py                  — гейт качества экзамена в новом формате (структура, формулы, рендер, PDF)
  tools/toc.py                          — пересборка оглавления README.md (столбец «Формат» на время перехода)
  TRANSITION.md                         — ход перехода на новый формат и инструкция для следующих сессий (временный файл)
  exams_math_and_phys.zip               — PDF условий всех основных экзаменов
```

## Перед любой работой

Выполнить `git pull`: владелец загружает файлы через веб-интерфейс GitHub, и локальная копия может отставать.

**Переход экзаменов на новый формат ещё идёт.** Состояние, порядок оставшихся пакетов и готовые задания для агентов — в [TRANSITION.md](TRANSITION.md); читать его перед любой работой над экзаменами, пока файл существует.

## Формат экзамена (спецификация)

Экзамен — markdown-файл по образцу существующих в `Exams/`. Длительность **180 минут**, один заход, **100 баллов**.

| Часть | Задач | Баллы | Время | Что проверяет |
|---|---|---|---|---|
| A. Определения и формулировки | 5 × 2 | 10 | ≈ 20 мин | Точные определения и теоремы со всеми условиями |
| B. Верно или неверно? | 5 × 3 | 15 | ≈ 25 мин | Границы теорем: короткое доказательство или контрпример |
| C. Стандартные задачи | 5 × 6 | 30 | ≈ 60 мин | Вычисления и типовые рассуждения |
| D. Ключевые доказательства | 3 × 10 | 30 | ≈ 45 мин | Центральные доказательства из банка КТ карточки |
| E. Повышенная сложность | 3 × 5 | 15 | ≈ 30 мин | Задачи без подсказанного пути |

**Разделы файла** (в этом порядке; скрипт PDF отрезает всё начиная с «## Карта навыков»):

1. `# <Код>. <Название> — диагностика` (для варианта — `…, вариант vN`).
2. Цитата-шапка: `**Код в плане:** [<Код>](../../PLAN.md#<код>) · **Время:** 180 минут · **Максимум:** 100 баллов · **Этап плана:** N`, затем `**Требует:** … **Можно пользоваться:** только бумагой и ручкой (никаких книг, конспектов, интернета, CAS).` Для вариантов — ещё строка «**Составлен:** …», для исправлений — строка «**Изменения:** …».
3. `## Как проходить` — четыре пункта, как в существующих экзаменах (засечь 180 минут; писать решения полностью; «Ключ в конце файла открывать только после окончания времени.»; «Записать баллы по частям в таблицу результатов в конце и прочитать интерпретацию.» — две последние фразы скрипт PDF заменяет, поэтому писать их дословно). При необходимости абзац «Соглашения» или «Обозначения».
4. `## Часть A. Определения и формулировки (≈ 20 мин, 10 баллов)` — «5 пунктов по 2 балла», нумерованный список. Пункт может объединять определение и связанную с ним теорему.
5. `## Часть B. Верно или неверно? (≈ 25 мин, 15 баллов)` — «5 пунктов по 3 балла». Утверждения, для которых нужно короткое доказательство или контрпример; большинство — неверные, проверяющие необходимость условий теорем.
6. `## Часть C. Стандартные задачи (≈ 60 мин, 30 баллов)` — **C1–C5** по 6 баллов, можно с пунктами (а), (б), ….
7. `## Часть D. Ключевые доказательства (≈ 45 мин, 30 баллов)` — **D1–D3** по 10 баллов, из банка КТ карточки в PLAN.md; в условии перечислено, что разрешено использовать без доказательства.
8. `## Часть E. Задачи повышенной сложности (≈ 30 мин, 15 баллов)` — **E1–E3** по 5 баллов.
9. `## Карта навыков` — таблица «Тема из „Содержания“ → задачи» и абзац, что перечитать по каждой теме (главы учебников карточки).
10. `## Результаты и интерпретация` — таблица «Часть / Максимум / Мои баллы», таблица уровней (0–39, 40–59, 60–74, 75–89, 90–100) с рекомендациями по учебникам карточки, абзац «**Правило галочки:** ставить `[x]` напротив <Код> в PLAN.md, если итог ≥ 75» и «**Диагностика по профилю:**» — 4–6 типичных профилей баллов и что они означают.
11. `## Ключ для самопроверки` — `<details><summary>Открыть только после окончания экзамена</summary>` (пустая строка после `<summary>`), подразделы `### Часть A` … `### Часть E`: ответы, схемы решений и критерии разбалловки по каждой задаче.

**Принципы составления.**

- **Покрытие.** v1 покрывает «Содержание» карточки как можно шире и равномернее: каждая тема представлена в A–D примерно одинаково по числу задач и баллам, самые важные моменты курса включены обязательно. Карта навыков должна это показывать: нет темы без задач и нет части, целиком отданной одной теме.
- **Часть D** — из банка КТ карточки; можно добавлять и другие доказательства дисциплины, важные для её понимания или для следующих дисциплин. Хотя бы одно из трёх — центральная теорема дисциплины. Доказательства должны укладываться в 15 минут каждое: длинные теоремы разбивать на части с разрешёнными леммами.
- **Трудность.** B и C проверяют понимание глубоко, но без искусственной сложности; E может быть заметно труднее. Помимо стандартных задач — немного интересных, в том числе в B и C. Экзамен должен быть реально написан за 180 минут на высокий балл человеком, глубоко знающим дисциплину, но видящим задачи впервые.
- **Часть E** — задачи, до которых можно додуматься, зная дисциплину и пререквизиты, но полезные для следующих тем программы; или содержательные сюжеты внутри дисциплины, не входящие в стандартные курсы.
- **Цель экзамена** — относительно быстрая проверка уровня понимания, а не олимпиада и не проверка памяти на оформление.
- **Варианты** (пересдачи, другие студенты) — по `Variants/README.md`: тот же формат, учёт отчётов студента, приоритет темам, не вошедшим в прошлые варианты.

**Качество.** Экзамен или вариант составляет сильная модель (агенты-составители и рецензенты запускаются на самой сильной доступной модели, даже если диалог ведёт более дешёвая). Каждое вычисление в ключе проверяется (`sympy`); файл проходит гейт `python3 -I "Reality Check/tools/verify_exam.py" <файл>` (структура, баллы, обязательные фразы, формулы, рендер через API GitHub, сборка PDF); затем независимый рецензент (отдельный агент, не видевший черновика) заново решает задачи вслепую, сверяет ключ, критерии и баланс покрытия и времени, исправляет ошибки минимальными правками и снова прогоняет гейт. После рецензии в строку «**Изменения:**» шапки дописывается «Независимая рецензия: <дата>.» — по этой пометке `tools/toc.py` отличает в оглавлении README «новый» от «новый, ждёт рецензии». Экзамен без пометки можно выдавать, но при первой возможности его нужно отрецензировать.

## Выдача экзаменов

- **«Хочу сдать <Код>»** (Leo, вариант v1). После `git pull`: `python3 "Reality Check/tools/exam_pdf.py" "Reality Check/Exams/<Область>/<файл>.md" -o "Reality Check/Students/Leo/<Код>/<сегодня>/exam.pdf"`. Скрипт печатает коммит; создать рядом `notes.md` по образцу из `Students/README.md` (студент, вариант, ссылка на файл, коммит, дата выдачи, пустые строки «Сдача», «Материалы», «Комментарий»), закоммитить и сразу запушить: владелец берёт PDF с GitHub. Перед выдачей открыть PDF (`pdftoppm` → картинки) и убедиться, что всё читается. Это механическая задача, с ней справляется любая модель.
- **«Выдай <Код> студенту <Имя>»** — то же, в `Students/<Имя>/…`, в `notes.md` указать студента.
- **Невыданный вариант.** Вариант считается выданным, если на него ссылается `notes.md` какой-нибудь попытки. Если в `Variants/<Код>/` лежит невыданный вариант, составленный для этого студента, выдать его, а не составлять новый. На «Хочу сдать <Код>», если у студента уже были попытки по коду, спросить, выдать ли вариант для пересдачи, а не v1.
- **«Сделай вариант для пересдачи <Код>»** (для Leo; для другого студента — «… студента <Имя>»). Прочитать все `REPORT.md` этого студента по коду, основной экзамен и прошлые варианты; составить `Variants/<Код>/vN.md` по `Variants/README.md`; пройти проверку качества; закоммитить; выдать как выше, с `--variant vN`.
- **Ключ не показывать.** Студент решает по `exam.pdf`; содержимое ключа в диалоге до проверки не пересказывать. Если другой студент сдаёт вариант, который Leo ещё не сдавал, после проверки в диалоге сообщать только баллы, уровень и общие замечания.

## Проверка

По `GRADING.md` полностью: самостоятельная проверка по существу, затем сверка с ключом; меньше строгости к оформлению (одноходовые переходы можно не расписывать), снимается пропуск содержательного шага; `REPORT.md` в папку попытки; строка в журнале `README.md`; для Leo при итоге ≥ 75 — `[x]` у кода во всех вхождениях в Части I `PLAN.md`. Для других студентов журнал заполняется, галочка не ставится.

## Архив PDF

`python3 "Reality Check/tools/exam_pdf.py" --zip "Reality Check/exams_math_and_phys.zip"` собирает PDF всех основных экзаменов из `Exams/`. Архив весит около 22 МБ, и каждая пересборка увеличивает репозиторий, поэтому пересобирать его только по просьбе владельца и одним коммитом после серии правок, а после правок экзаменов — говорить, что архив устарел. Если скрипт пишет «ВНИМАНИЕ» (нет глифа, строка вылезает за поле), посмотреть PDF и поправить скрипт, а не экзамен.

## Правки программы

- Галочки — в Части I `PLAN.md` у всех вхождений кода; атлас (Часть III) при проверке не трогать.
- Карточки атласа (содержание, зависимости, банк КТ) менять по просьбе владельца или при обнаружении ошибки, не выдумывая нового; при изменении «Требует» согласовывать графы в Части II и «Нужна для» у соседей.
- Коды дисциплин (`A4`, `G9`, …) и якоря `#a4` не менять: на них ссылаются экзамены, отчёты и журнал.

## Соглашения

- Типографика: «ёлочки», длинное тире —, буква ё.
- Внутри `<details>` после `<summary>` обязательно пустая строка.
- Новые экзамены и варианты — по шаблону существующих файлов в `Exams/`, включая оформление формул (см. ниже).
- Коммиты делаются прямо в `main`. Пушить на GitHub, если владелец просил или подтвердил; выдачу экзамена пушить сразу.
- Сообщения коммитов: `Reality Check: <что сделано>`, например `Reality Check: проверка A4 Leo от 2026-10-21 — 17/100`, `A6: экзамен переведён в новый формат`.

## Формулы

Всё ниже проверено на GitHub в браузере. Обычный синтаксис `$...$` и `$$...$$` не использовать: GitHub сначала разбирает Markdown, поэтому `_` внутри формулы может стать курсивом, `\,` превращается в запятую, `\\` — в `\`, `\{` — в `{`.

- **Строчные формулы** — `` $`...`$ ``: `` $`\mathbb{G}_m`$ ``. Внутри обратных кавычек Markdown не трогает `_`, `*`, `\,`, `\\`, `\{`, `<`.
- **Выключные формулы вне `<details>`** — блок `math` с пустыми строками до и после:

  ````
  ```math
  \mathrm{Hom}(A,B)\to\mathrm{Hom}(B,C)
  ```
  ````

- **Выключные формулы внутри `<details>`** (ключ, решения) — через центрированный `` $`\displaystyle ...`$ `` (этот вариант проверен в браузере). Писать так, с пустыми строками вокруг каждой строки и обязательно после `</div>`:

  ```
  <div align="center">

  $`\displaystyle \dim\Gamma_d=mn.`$

  </div>

  Текст дальше…
  ```

  Если после `</div>` сразу идёт текст, GitHub считает его продолжением HTML-блока и показывает формулы с обратными кавычками.
- **Операторы** — `\mathrm{...}`. `\operatorname` на GitHub запрещён и выдаёт ошибку. `\mathrm` не ставит пробелов сам, поэтому добавлять `\,`:
  - справа, если дальше операнд, а не скобка: `\mathrm{Spec}\,A`, `\mathrm{tr}\,A`, `\mathrm{rk}_{\mathbb{C}}\,\omega` (пробел после индекса);
  - слева, если перед оператором буква, цифра или закрывающая скобка: `2\,\mathrm{Re}\,z`, `(-1)^i\,\mathrm{Tr}(\dots)`;
  - не нужен перед скобкой (`\mathrm{Gal}(L/K)`), после `=`, `\to`, `(` и рядом с `|`.
- **`\mathbb`** — только заглавные латинские буквы. Для единицы — `\mathbf{1}`, для поля — `k` или `\Bbbk`.
- **Таблицы:** формулы с `|` в ячейках не писать (`|` делит ячейку даже внутри формулы); модуль — `\lvert x\rvert`. Сложные формулы в таблицы лучше не ставить вовсе.
- **Проверка:** отрендерить файл через `gh api markdown -f mode=gfm -f context=NeuroWorknotNeo/Leo -F text=@файл.md`. Каждая формула должна оказаться целиком внутри одного `<math-renderer>`, без обратных кавычек и `<em>` внутри. Голых `$` вне формул в тексте быть не должно. Сообщения «Unable to render expression» в headless-браузере на страницах с сотнями формул — ложная тревога, если проверка через API прошла.
- В PDF формулы попадают через pdfLaTeX: не использовать команды, которых нет в amsmath/amssymb/mathtools/mathrsfs; кириллица внутри формул автоматически оборачивается в `\text{}`.
