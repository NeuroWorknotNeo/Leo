# Leo — заметки для Claude

Личный репозиторий для изучения математики по плану вплоть до уровня современных исследований. Общение и все файлы — на русском языке.

## Структура

- `plan.md` — атлас дисциплин и трекер прогресса. Чекбоксы стоят в Части I, карточки дисциплин с якорями `#a1`, `#g9` и т. п. — в Части III.
- `Galois Theory/` — письменные разборы владельца (PDF).
- `Reality Check/` — диагностики по каждой дисциплине плана (78 экзаменов, части A–E, 100 баллов; обычно 120 минут; A4 — 180 минут, расширенные экзамены по физике дольше — см. «Особые правила для экзаменов по физике» в `README.md`):
  - `README.md` — правила, шкала уровней, журнал попыток, оглавление;
  - `GRADING.md` — протокол проверки;
  - `Attempts/<Код>/<дата выдачи>/` — попытки: `exam.pdf` (условия), `notes.md` (вариант, коммит, условия сдачи), решения, `REPORT.md`;
  - `Variants/<Код>/vN.md` — варианты экзаменов для пересдач (с ключом), правила — в `Variants/README.md`;
  - `tools/exam_pdf.py` — сборка PDF с условиями (без карты навыков, интерпретации и ключа);
  - `exams_math_and_phys.zip` — PDF условий всех основных экзаменов.

## Перед любой работой

Выполнить `git pull`: владелец загружает файлы через веб-интерфейс GitHub.

## Проверка экзаменов

Когда просят проверить или оценить попытку экзамена, следовать `Reality Check/GRADING.md` полностью: строгая оценка, отчёт `REPORT.md`, запись в журнал, галочка в `plan.md` при выполнении критерия.

## Выдача экзаменов и варианты

Схема для владельца описана в разделе «Как сдавать» в `Reality Check/README.md`. Что делает Claude:

- **«Хочу сдать <Код>»** (вариант v1). После `git pull`: `python3 "Reality Check/tools/exam_pdf.py" "<файл экзамена>" -o "Reality Check/Attempts/<Код>/<сегодня>/exam.pdf"`. Скрипт печатает коммит; создать рядом `notes.md` по образцу `Attempts/A2/2026-10-21/notes.md` (вариант, ссылка на файл, коммит, дата выдачи, пустые строки «Сдача», «Материалы», «Комментарий»), закоммитить и сразу запушить: владелец берёт PDF с GitHub. Перед выдачей открыть PDF (`pdftoppm` → картинки) и убедиться, что всё читается. Это механическая задача, с ней справляется любая модель.
- **Невыданный вариант.** Вариант считается выданным, если на него ссылается `notes.md` какой-нибудь попытки. Если в `Variants/<Код>/` лежит невыданный вариант, то на «Сделай вариант для пересдачи <Код>» новый не составлять, а выдать готовый. На «Хочу сдать <Код>», если по коду уже были попытки, — спросить, выдать ли этот вариант (пересдача обычно идёт по нему), а не v1.
- **«Сделай вариант для пересдачи <Код>»**. Прочитать все `REPORT.md` этого кода и основной экзамен; составить `Variants/<Код>/vN.md` по правилам `Variants/README.md` (та же структура и контрольная точка, новые задачи, упор на слабые темы). Это дорогая и ответственная работа: сильная модель, все вычисления проверять в `sympy`, затем независимая рецензия (отдельный агент решает задачи заново и сверяет ключ), формулы — проверка через API GitHub (см. ниже). Закоммитить вариант, затем выдать его как выше, с `--variant vN`.
- **Ключ не показывать.** Владелец решает по `exam.pdf`; содержимое ключа в диалоге до проверки не пересказывать.
- **Архив `exams_math_and_phys.zip`** пересобирать, когда менялись условия экзаменов: `python3 "Reality Check/tools/exam_pdf.py" --zip "Reality Check/exams_math_and_phys.zip"`. Архив весит около 22 МБ, и каждая пересборка увеличивает репозиторий, поэтому — одним коммитом после серии правок, а не после каждой.
- Если скрипт пишет «ВНИМАНИЕ» (нет глифа, строка вылезает за поле), посмотреть PDF и поправить скрипт, а не экзамен.

## Соглашения

- Типографика: «ёлочки», длинное тире —, буква ё.
- Внутри `<details>` после `<summary>` обязательно пустая строка.
- Новые диагностики или варианты — по шаблону существующих файлов в `Reality Check/`, включая оформление формул (см. ниже).
- Коммиты делаются прямо в `main`. Пушить на GitHub, если владелец просил или подтвердил.

## Формулы

Всё ниже проверено на GitHub в браузере. Обычный синтаксис `$...$` и `$$...$$` не использовать: GitHub сначала разбирает Markdown, поэтому `_` внутри формулы может стать курсивом, `\,` превращается в запятую, `\\` — в `\`, `\{` — в `{`.

- **Строчные формулы** — `` $`...`$ ``: `` $`\mathbb{G}_m`$ ``. Внутри обратных кавычек Markdown не трогает `_`, `*`, `\,`, `\\`, `\{`, `<`.
- **Выключные формулы вне `<details>`** — блок `math` с пустыми строками до и после:

  ````
  ```math
  \mathrm{Hom}(A,B)\to\mathrm{Hom}(B,C)
  ```
  ````

- **Выключные формулы внутри `<details>`** (ключ, решения) — как во всех экзаменах, через центрированный `` $`\displaystyle ...`$ `` (этот вариант проверен в браузере). Писать так, с пустыми строками вокруг каждой строки и обязательно после `</div>`:

  ```
  <div align="center">

  $`\displaystyle \dim\Gamma_d=mn.`$

  </div>

  Текст дальше…
  ```

  Если после `</div>` сразу идёт текст, GitHub считает его продолжением HTML-блока и показывает формулы с обратными кавычками.
- **Операторы** — `\mathrm{...}`. `\operatorname` на GitHub запрещён и выдаёт ошибку. `\mathrm` не ставит пробелов сам, поэтому добавлять `\,`:
  - справа, если дальше операнд, а не скобка: `\mathrm{Spec}\,A`, `\mathrm{tr}\,A`, `\mathrm{rk}_{\mathbb{C}}\,\omega` (пробел после индекса);
  - слева, если перед оператором буква, цифра или закрывающая скобка: `2\,\mathrm{Re}\,z`, `(-1)^i\,\mathrm{Tr}(\dots)`;
  - не нужен перед скобкой (`\mathrm{Gal}(L/K)`), после `=`, `\to`, `(` и рядом с `|`.
- **`\mathbb`** — только заглавные латинские буквы. Для единицы — `\mathbf{1}`, для поля — `k` или `\Bbbk`.
- **Таблицы:** формулы с `|` в ячейках не писать (`|` делит ячейку даже внутри формулы); модуль — `\lvert x\rvert`. Сложные формулы в таблицы лучше не ставить вовсе.
- **Проверка:** при сомнениях отрендерить фрагмент через `gh api markdown -f mode=gfm -f context=NeuroWorknotNeo/Leo -F text=@файл.md`. Каждая формула должна оказаться целиком внутри одного `<math-renderer>`, без обратных кавычек и `<em>` внутри. Голых `$` вне формул в тексте быть не должно.
